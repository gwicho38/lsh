# LSH v4.0.0 Release Notes

**Release Date:** 2026-08-28

## Changes from v3.2.5

## Breaking Change: The CLI Surface Is Now Five Commands

v3 had 23 top-level commands. v4 has five, plus `help`. `lsh --help` now lists exactly six entries: `help`, `push`,
`pull`, `sync`, `edit`, `list`. Every command that used to be its own top-level entry — setup, keys, config, health,
IPFS management, individual secret get/set, sync history, self-update, shell completion, and more — is either a flag
on one of the five, or gone outright. Running any old command name fails immediately with the v4 replacement:

```
$ lsh key
error: 'lsh key' was removed in v4.0.0
  use: lsh sync --key (import: lsh sync --key=<value>, generate: lsh sync --init)
```

### `lsh push`

Encrypt the local .env and push it to cloud storage.

| Flag | Description | Default |
|---|---|---|
| `-f, --file <path>` | Path to .env file | `.env` |
| `-e, --env <name>` | Environment name (dev/staging/prod) | `dev` |
| `-g, --global` | Use global workspace ($HOME) | off |
| `--force` | Push even if destructive changes are detected | off |

### `lsh pull`

Pull and decrypt a .env from cloud storage.

| Flag | Description | Default |
|---|---|---|
| `-f, --file <path>` | Path to .env file | `.env` |
| `-e, --env <name>` | Environment name | `dev` |
| `-g, --global` | Use global workspace ($HOME) | off |
| `--force` | Overwrite without creating a backup | off |
| `--cid <cid>` | Pull an exact CID instead of resolving via IPNS | — |
| `-r, --repo <name>` | Source repo name for IPNS resolution | — |

### `lsh sync`

Two-way sync of secrets, plus setup, keys, config, and health. Bare `lsh sync` pushes or pulls, whichever side is
newer; every other v3 command that used to manage setup, keys, config, or health is now a flag here.

| Flag | Description | Default |
|---|---|---|
| `-f, --file <path>` | Path to .env file | `.env` |
| `-e, --env <name>` | Environment name | `dev` |
| `-g, --global` | Use global workspace ($HOME) | off |
| `--force` | Accept destructive actions: sync past change detection, or replace an existing key | off |
| `--load` | Print `export` lines for `eval "$(lsh sync --load)"` | off |
| `--status` | Show context, tracked environment, and IPFS state | off |
| `--format <table\|json>` | Output format for `--status`, `--history`, `--config` | `table` |
| `--init` | Run the setup wizard (installs IPFS, generates a key) | off |
| `--key [value]` | Print the encryption key, or import one | off |
| `--config` | Print the resolved configuration and its source path | off |
| `--doctor` | Run a health check | off |
| `--repair` | Clear local sync history and secrets metadata to unstick registries | off |
| `--history` | Show immutable IPFS sync records | off |
| `--verify <cid>` | Check that a CID is retrievable | — |

### `lsh edit`

Edit the local .env, then optionally push the change.

| Flag | Description | Default |
|---|---|---|
| `-f, --file <path>` | Path to .env file | `.env` |
| `-e, --env <name>` | Environment name | `dev` |
| `-g, --global` | Use global workspace ($HOME) | off |
| `--get [key]` | Print one value, or every value with `--all` | off |
| `--all` | With `--get`, print every value | off |
| `--set <assignment>` | Set `KEY=VALUE` | — |
| `--list` | Print a masked table of keys | off |
| `--copy-from <env>` | Merge another environment's vars into this one | — |
| `--no-push` | Never prompt to push after editing | off |
| `--format <format>` | Output format: `env`, `json`, `yaml`, `toml`, `export` | `env` |

With no read/write flag, `lsh edit` opens `$EDITOR` (falling back to `$VISUAL`, then `vi`) on the local `.env`,
diffs the result, and prompts to push if anything changed and the session is interactive.

### `lsh list`

List secrets in the current local `.env` file. Read-only — unlike `edit --list`, this does not accept `-e/--env`.

| Flag | Description | Default |
|---|---|---|
| `-f, --file <path>` | Path to .env file | `.env` |
| `-g, --global` | Use global workspace ($HOME) | off |
| `--keys-only` | Show only keys, not values | off |
| `--format <format>` | Output format: `env`, `json`, `yaml`, `toml`, `export` | `env` |
| `--no-mask` | Show full values | off (masked) |

`lsh list` always masks unless `--no-mask` is given, for every format — not just `env`. `--format export` routes
through the same key-name guard as `edit --format export`, so a key that isn't a valid shell identifier fails the
command instead of emitting an executable line. Aliased as `lsh ls`.

### `-g/--global` survives on every command

v3.1.1 extended `-g/--global` to all sixteen top-level commands that existed at the time. That flag was not dropped
in the consolidation — all five v4 commands (`push`, `pull`, `sync`, `edit`, `list`) accept `-g/--global`, with the
same meaning: operate against `$HOME` instead of the current directory.

## Removed Commands

Generated from `REMOVED_COMMANDS` in `src/lib/removed-commands.ts` — this table and the CLI's own error messages
are the same source, so they cannot disagree. `lsh list` / `lsh ls` are not in this table — they survive as their
own top-level command; see [`lsh list`](#lsh-list) above.

| v3 command | v4 replacement |
|---|---|
| `lsh get <key>` | `lsh edit --get <key>` |
| `lsh set <key> <value>` | `lsh edit --set <key>=<value>` |
| `lsh env` | `lsh edit --get --all --format env` |
| `lsh load` | `lsh sync --load` |
| `lsh create` | `lsh edit` |
| `lsh delete` | `rm .env` |
| `lsh cp <from> <to>` | `lsh edit --env <to> --copy-from <from>` |
| `lsh key` | `lsh sync --key` (import: `lsh sync --key=<value>`, generate: `lsh sync --init`) |
| `lsh init` | `lsh sync --init` |
| `lsh doctor` | `lsh sync --doctor` |
| `lsh config` | `lsh sync --config` |
| `lsh status` | `lsh sync --status` |
| `lsh info` | `lsh sync --status` |
| `lsh clear` | `lsh sync --repair` |
| `lsh sync-history` | `lsh sync --history` |
| `lsh ipfs` | nothing — push, pull, and sync manage the IPFS daemon automatically |
| `lsh migrate` | nothing — this migrated v1.x to v2.0 and is obsolete |
| `lsh self` | `npm install -g lsh-framework` (version: `lsh --version`) |
| `lsh context` | `cat llms.txt` |
| `lsh completion` | nothing — shell completion was removed in v4.0.0 |

### Removed `lsh sync` subcommands

v3's `sync` was itself a subcommand group. Generated from `REMOVED_SYNC_SUBCOMMANDS` in the same file:

| v3 `lsh sync <subcommand>` | v4 replacement |
|---|---|
| `lsh sync push` | `lsh push` |
| `lsh sync pull` | `lsh pull` |
| `lsh sync now` | `lsh sync` |
| `lsh sync init` | `lsh sync --init` |
| `lsh sync status` | `lsh sync --status` |
| `lsh sync history` | `lsh sync --history` |
| `lsh sync clear` | `lsh sync --repair` |
| `lsh sync verify <cid>` | `lsh sync --verify <cid>` |
| `lsh sync start` | nothing — the IPFS daemon starts automatically |
| `lsh sync stop` | nothing — the IPFS daemon is managed automatically |

## Pre-release Fixes

Found and fixed in the final review pass before this release, listed here because each one changes documented
behavior above:

- **`sync --key` now also refuses a write that would shadow the encryption key actually in effect**, not just a
  key already sitting in the file being written. Importing a project key into `./.env` while `~/.env` holds a
  different one used to succeed silently and permanently orphan secrets pushed under the old key; it now refuses
  (`--force` still overrides).
- **`edit --set` and `--copy-from` patch the target line in place** instead of rewriting the whole `.env` through
  a parse/serialize round-trip. Comments, blank lines, and untouched values (including an unquoted trailing `#`
  in a value) survive byte-for-byte, and a `.env.backup.<timestamp>` is written before either command touches an
  existing file.
- **The push confirmation prompt (`Push to <env>? [Y/n]`) now treats `no` as `no`.** Only empty input, `y`, or
  `yes` proceed; anything else, including unrecognized input, cancels.
- **`.gitignore` entries added by LSH now also cover `.env.copyfrom.*` and `.env.backup.*`**, so the temp file
  `edit --copy-from` uses and the new `--set`/`--copy-from` backups can't be staged by `git add .`.
- **`lsh env`'s replacement is now `lsh edit --get --all --format env`**, not `lsh edit --list --format env` —
  `--list` masks values, and v3's `lsh env` printed real ones.
- **`sync --repair` now also clears `~/.lsh/secrets-metadata.json`**, not just the IPFS sync history. `lsh clear`
  deleted that file in v3; `--repair` is its full v4 replacement now, not a partial one.
- **`.gitignore` coverage now follows the file `edit` actually writes**, not just the literal `.env.backup.*`
  pattern. `edit --set --file app.env` used to leave `app.env.backup.<timestamp>` stageable by `git add .`;
  the target's own basename and `<basename>.backup.*` are now added, and a freshly created target file (one
  that didn't exist yet) is covered before it's written, not only on the backup-of-an-existing-file path.
- **`edit --set` resolves a duplicated key last-wins**, matching how the file itself resolves (and dotenv).
  Updating a key that appears more than once in the file used to patch only the first occurrence, leaving a
  later duplicate — and therefore `edit --get` — still returning the old value even though `--set` reported
  success. The last occurrence is now updated and earlier duplicates are dropped.
- **`sync --key` now persists a key that's already effective from another source but absent from the file
  being written**, instead of treating "effective" as "already configured" and silently writing nothing.
  The no-op is now scoped to the target file itself already holding the exact key; the shadow refusal (above)
  is unchanged and still blocks a write that would make a *different* key effective.

## Three Accepted Losses

Most of the table above is a mechanical flag rename with no loss of capability. Three commands narrow or disappear
outright, and that's intentional:

- **`lsh cp <from> <to>` narrows to `lsh edit --env <to> --copy-from <from>`.** The v3 command copied secrets
  between two environments in one step with no local file involved. The v4 replacement goes through `edit`, which
  merges the source environment's values into the local `.env` for the target environment and then offers to push —
  functionally equivalent, but it now touches the local file instead of copying cloud-to-cloud directly.
- **`lsh delete` is removed. Use `rm .env`.** Deleting the local file was the entire implementation; there's no
  cloud-side deletion to wrap it around, so a dedicated command added a command name without adding capability.
- **`lsh completion` is removed outright, with no replacement.** Shell completion for a four-command CLI has a low
  enough payoff that maintaining a completion script generator for `bash`/`zsh` stopped being worth it. If you had
  completion sourced from your shell profile, remove that line — see [Upgrading](#upgrading) below.

## IPFS Lifecycle Is Now Automatic

The `lsh ipfs` command group (`status`, `install`, `uninstall`, `init`, `start`, `stop`) is gone. `push`, `pull`, and
`sync` each call `IPFSClientManager.ensureDaemonRunning()` before they touch the network — this installs Kubo if
it's missing, initializes the repository if needed, and starts the daemon if it isn't already running. There is no
separate install or start step to run yourself. See
[docs/features/ipfs/IPFS_CLIENT_GUIDE.md](../features/ipfs/IPFS_CLIENT_GUIDE.md) for manual recovery paths.

## Bug Fixes

- **`edit --set --no-push` named a blank environment in its hint** (`Not pushed. Run: lsh push --env `). It now
  names the real environment, or drops the `--env` fragment entirely when the environment is the git-derived
  default — matching what bare `lsh push` would resolve to anyway.

## Upgrading

Five rewrites cover the large majority of what a daily user actually types:

**Setup**
```bash
# v3
lsh init

# v4
lsh sync --init
```

**Reading a single secret**
```bash
# v3
lsh get API_KEY

# v4
lsh edit --get API_KEY
```

**Setting a single secret**
```bash
# v3
lsh set API_KEY my-api-key-value

# v4
lsh edit --set API_KEY=my-api-key-value
```

**Checking sync status**
```bash
# v3
lsh status

# v4
lsh sync --status
```

**Listing secrets / loading them into the shell**
```bash
# v3
lsh list --format export
eval "$(lsh sync --load)"

# v4
lsh list --format export    # unchanged
eval "$(lsh sync --load)"   # unchanged
```

For every other v3 command, run it once — the v4 CLI's error message names the exact replacement — or consult the
full removal tables above.
